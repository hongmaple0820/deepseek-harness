# Agent Note: 可携带的用户数据备份与同步

Status: proposed

[English](2026-11-13-portable-user-data-backup.md) | 中文

## Problem

一次 DSH 安装的工作状态分散在几处，没有任何单一操作可以把它们整体搬走：`profiles/<name>/package.json` 与 `cordis.patch.yml` 保存已安装插件及其配置，volatile 设置落进同一个 profile patch，会话位于 `sessions/`，插件通过 `ctx.storage` 保存非会话记录，凭据则在 `.credentials.yaml` 与 `.env` 中。因此换一台机器等于从零开始：用户要重装插件、重填设置，旧会话也无法访问。

单会话导出已经存在，见 [session-log-export](../../../../packages/session-query/session-log-export/README.zh.md)（`/api/session.export` 与 `/api/session.markdown`，ZIP 内含 `session.vN.jsonl`、子会话、media、files 以及附件缺失报告）。但没有路径可以导出或恢复设置、插件配置、storage 记录或一组会话，也没有任何路径把其中任一项搬到另一台机器。

## Proposal

增加备份包及其恢复路径，然后把远端传输做成由同一个备份包驱动的插件。

### 备份包内容

一个 ZIP，开头是 `manifest.json`，随后每个被选中的组件一个目录。manifest 记录备份包 schema 版本、写入它的 DSH 版本、profile 名称、包含会话时的会话格式版本，以及每个组件的文件数、字节数、是否脱敏。

| 组件 | 默认 | 内容 |
|---|---|---|
| `profile` | 开启 | `profiles/<name>/package.json` 与 `cordis.patch.yml` |
| `settings` | 开启，secret 脱敏 | profile patch 中的 volatile 设置段，每个 secret 替换为存在标记 |
| `sessions` | 关闭 | 沿用现有单会话归档布局，按选中会话逐个写入 |
| `credentials` | 关闭 | `.credentials.yaml` 与 `.env` |

会话与凭据默认关闭，因为它们是体积与敏感性最高的两个组件。选中任一组件时，导出前会先说明将写入什么。

脱敏把 secret 值替换为存在标记，并把键记入 manifest 的脱敏列表。导入时标记恢复为未设置，导入报告会列出用户需要重新填写的每个键。凭据组件不脱敏，因为用户是知情选择的；导出仍然报告字节数，并在目标路径位于仓库内部时拒绝执行。

### 导出与导入

导出与导入在 Host 内运行，紧邻会话导出端点，由设置界面驱动。导入分两步：

1. **预览。** 读取备份包、校验 manifest，按组件报告：新增条目数、覆盖本地值的条目数、因本地值更新而跳过的条目数，以及缺少 secret 而无法恢复的键。此步不写入任何内容。
2. **应用。** 写入被接受的组件，并把被替换的每个文件保留一份带时间戳的副本，因此误导入可以在同一界面撤销。

冲突按组件显式决定，永不做静默合并：保留本地、覆盖本地或跳过。只有预览处做这个决定，因为备份包是快照而不是历史。

### 同步

同步就是同一个备份包存放在远端目标上，而不是第二套数据模型。目标是实现一个窄接口的插件——列出备份包、上传备份包、按 id 下载备份包——首批实现为 WebDAV 与 S3。备份包一旦上传即不可变，每次上传新增序号而不覆盖，因此恢复是挑选一个快照，而不是合并两段历史。保留策略按 profile 保留最近 N 个备份包且可配置，设置界面列出它们的时间、大小与写入它的 DSH 版本。

自动上传按组件启用且默认关闭；为会话启用与为设置启用是两个独立开关。

## Alternatives considered

- **打包整个 DSH home。** 一个 tar 覆盖全部内容，是实现量最小的方案，但它未经决定就带上凭据、包含缓存与日志，且导入没有审阅步骤。仅作为显式的 `full` 选择保留，其中包含凭据。
- **对会话与设置做三方合并。** 同步能保住并发修改，但会话是由 session 包拥有的追加型日志，设置在多台机器之间也没有全序，两边的合并语义都需要新的归属方。此项推迟；快照加按快照的 last-write-wins 让第一版如实说明它能承诺什么。
- **把云 SDK 放进 Host。** 在 Host 内加入 WebDAV 与 S3 客户端会让每个未来目标都变成核心改动。传输留在备份包接口之后的插件里，第三方目标不增加 Host 代码。

## Acceptance criteria

- 导出的备份包导入空的 `DSH_HOME` 后，得到相同的插件集合、相同的设置值，以及在包含会话时同一版本可以打开的会话。
- 默认导出不含任何 secret 值；导入被脱敏的备份包会报告每个需要填值的键。
- 预览不写入任何内容，并按组件报告新增、覆盖与跳过的数量。
- WebDAV 与 S3 目标可以完成备份包往返，从任一目标恢复得到与从本地文件恢复相同的状态。
- 导出与导入不改变磁盘上的会话文件；会话格式版本不兼容的备份包被拒绝，并在报告中给出两个版本。

## Risks

- 会话树较大时导出缓慢且备份包很大。缓解：按组件选择、流式创建 ZIP，并由 Host 报告进度。
- 脱敏只知道被告知的键，插件可以把 secret 存进一个普通设置键。缓解：预览会列出看起来像凭据的每个设置值，且导出永不记录备份包内容。
- 向更新的 DSH 恢复时可能遇到更旧的会话格式。缓解：manifest 携带会话格式版本，导入选择拒绝而不是转换。
- 两台机器向同一目标上传会竞争，last-write-wins 会丢掉一个快照。缓解：不可变编号备份包、manifest 中的按机器 profile 名称，以及按快照恢复而非隐式合并。
